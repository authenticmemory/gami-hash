# Linux download signing

## What is implemented

The Linux GUI and CLI workflows require the shared security workflow and the
`linux-signing` GitHub environment. Matching `test-v*` and `v*` tags, or manual
runs, produce detached ASCII-armored OpenPGP signatures (`.asc`) for every
published Linux package/tarball and its checksum file. Each signature is verified
in a separate public-only keyring before upload. Missing keys or failed
verification fail the job. No production key is generated by CI.

This is direct-download authentication. It does NOT embed an RPM signature,
configure APT/DNF trust, or establish a signed package repository. Installing a
`.deb` with `apt install ./file.deb` does not verify its detached signature for you.
Users must perform the verification below first. Packages still require Linux
installation/runtime acceptance testing; signing does not establish compatibility.

## One-time setup by the organization's release owner

Use a trusted administrator computer with GnuPG installed. The following commands
are for a Linux terminal (or WSL), not PowerShell. Keep the primary key and its
revocation certificate in encrypted offline storage with an organizational backup.
Do not create keys on an ephemeral GitHub runner or paste them into a chat.

1. Create a certification-only primary key. GnuPG prompts for a strong passphrase:

   ```bash
   gpg --quick-generate-key 'Authentic Memory Linux Releases <tech@authenticmemory.org>' rsa4096 cert 2y
   gpg --list-keys --with-subkey-fingerprint 'Authentic Memory Linux Releases'
   ```

2. Copy the FULL primary fingerprint, replace the placeholder below, and add a
   signing subkey. Record a renewal reminder before its expiry:

   ```bash
   FINGERPRINT='REPLACE_WITH_FULL_PRIMARY_FINGERPRINT'
   gpg --quick-add-key "$FINGERPRINT" rsa4096 sign 1y
   gpg --armor --output gami-linux-public.asc --export "$FINGERPRINT"
   gpg --armor --output gami-linux-ci-secret.asc --export-secret-subkeys "$FINGERPRINT"
   ```

   The secret-subkeys export allows CI signing without the primary certification
   private key. Protect it and its passphrase as release credentials. Never commit
   either to Git, upload them as workflow artifacts, or place them in website files.

3. In `authenticmemory/gami-hash`, open **Settings > Environments**, create
   **linux-signing**, and restrict deployments to your trusted release branch and
   tag patterns `test-v*` and `v*`. Restrict who may push those tags. Add required
   reviewers if available for your repository plan.

4. Add these under that environment:

   | Type | Name | Value |
   | --- | --- | --- |
   | Secret | `LINUX_SIGNING_PRIVATE_KEY` | Entire contents of `gami-linux-ci-secret.asc`, including armor headers |
   | Secret | `LINUX_SIGNING_PASSPHRASE` | The signing subkey's passphrase |
   | Variable | `LINUX_SIGNING_FINGERPRINT` | Full primary fingerprint without spaces |

   A passphrase and key in the same CI environment are not independent protection
   against a compromised authorized workflow. Environment access and trusted
   release revisions remain the signing boundary. Hardware-backed signing can be
   introduced later without changing the public verification model.

5. Publish `gami-linux-public.asc` and the full primary fingerprint on the official
   website through a reviewed change. CI also bundles a public key, but a public
   key downloaded beside a binary is not an independent proof of identity. Users
   must compare its fingerprint to the organization's separately published value.

6. Push the workflow changes and a fresh test tag. Download the resulting Linux
   artifacts, verify them, and test installation on the target distributions.
   The existing uploads expire after 14 days; copy the verified artifacts and
   signatures into the reviewed release for durable distribution. The website's
   Linux download remains unavailable until approved packages are provided.

## Verify a direct download before installation

Install GnuPG using your distribution's normal package manager. Put the public key,
artifact, signature, and checksum files in one directory. In a terminal there:

```bash
gpg --show-keys --with-fingerprint gami-linux-signing-key.asc
# Compare the full primary fingerprint to the official website BEFORE importing.
gpg --import gami-linux-signing-key.asc
gpg --verify SHA256SUMS-linux-gui.txt.asc SHA256SUMS-linux-gui.txt
sha256sum --check SHA256SUMS-linux-gui.txt
# Replace this example with the actual downloaded filename:
gpg --verify gami-hash_1.0.0_amd64.deb.asc gami-hash_1.0.0_amd64.deb
```

Expect a good signature from the expected key, command exit code zero, and `OK`
for every checksum. Keep all files listed in the checksum list together. For the
CLI use `gami-hash-linux-amd64.tar.gz.sha256` and its `.asc` instead.
GnuPG may warn that a key is not certified by a trusted signature: a good
cryptographic signature alone does not establish its owner. The independent
fingerprint comparison is essential. Stop on a bad signature or mismatched hash.

## Key maintenance

Document the custodian, expiry dates, backup location, and recovery process.
Before expiry, renew with the offline primary key and replace the CI subkey export
and public key. On suspected compromise, disable signing, revoke the affected key,
publish the revocation and replacement fingerprint, and investigate affected
releases. Do not silently replace keys or rewrite published release artifacts.
